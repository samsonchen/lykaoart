# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repository is

A static, pre-rendered mirror of the WordPress site **lykaoart.com** (artist 高連永 — 書法 / 篆刻 / 硯銘 / 金石) preserved for hosting on GitHub Pages. There is no build step, no test suite, no package manifest, and no server-side code — only HTML, CSS, JS, and images captured from the original WordPress install.

The repo is served as-is. Anything committed at a given path appears at that path on the live site.

## No commands to run

There is no build, no test runner, no linter, no dev server defined in the repo. To preview locally, serve the directory with any static file server (e.g. `python3 -m http.server`) from the repo root. Do not invent build/test commands — there are none to run.

## Layout conventions inherited from the WordPress mirror

The directory structure is **not** a hand-authored site; it is the output of a recursive mirror of the WordPress site, so several conventions look strange but are load-bearing:

- **Post pages use literal `@p=N.html` filenames** (e.g. `index.html@p=129.html`). These come from WordPress's `?p=N` query strings being flattened into filenames by the mirroring tool. Hrefs throughout the site point at these exact names — do not "clean them up" or URL-decode them.
- **Asset filenames embed the original version querystring**, e.g. `wp-content/themes/vega/css/screen.css@ver=3.4.css`. The trailing `.css` / `.js` extension after `@ver=...` is what makes the static server set the right Content-Type. Renaming breaks the page.
- **Top-level category directories are Chinese (UTF-8)**: `首頁/`, `書法/`, `篆刻/`, `硯銘/`, `2018-展覽/`. Each contains an `index.html` plus sub-category folders (also Chinese). When running shell commands against these paths, quote them. If `git status` shows mojibake, the repo's `core.quotePath` is the cause, not actual file corruption.
- **`.nojekyll`** at the root is required: it tells GitHub Pages to skip Jekyll preprocessing, which would otherwise hide `_`-prefixed paths and choke on the unusual filenames. Do not delete it.

## Vestigial absolute URLs

Many pages still contain absolute references to `http://www.lykaoart.com/...` (xmlrpc, RSS feeds, pingback endpoints, occasional inline links). These are dead on the GitHub Pages host but harmless. Only rewrite them if a specific link is broken in user-facing navigation — bulk-rewriting risks corrupting the captured markup.

## When editing content

- The HTML was generated by WordPress + the `vega` theme (in `wp-content/themes/vega/`); the markup is verbose and template-driven. Treat each `index.html@p=*.html` as an independent static snapshot — there is no shared template to regenerate them from.
- Images live under `wp-content/uploads/YYYY/MM/` mirroring WordPress's upload organization.
- Adding a new post-like page means hand-authoring the HTML and any links into it, not generating it through a tool.
